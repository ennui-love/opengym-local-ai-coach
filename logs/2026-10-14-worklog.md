## 阶段 3 · 需求澄清：为什么要 Docker

用户追问「装 Docker 是不是为了引入 AI 规划训练」。复查 README 确认 openGym 确有 **AI Coach** 功能：

- 默认**关闭**（opt-in）。
- **只运行在自建 Docker 服务器上**，使用用户自己的 LLM provider key。
- 支持的 provider：Anthropic / OpenAI / Gemini / OpenAI 兼容 / Ollama。
- **手机 local mode 没有后端，因此无法使用 AI Coach。**

结论：非 AI 的进阶规则（progression：linear / Greyskull LP / 双三进阶 / deload）、1RM 估算、肌肉热力图在 local mode 下都可用且零费用；**要真正用 AI 规划，就必须重建 Docker 部署并配模型**。

## 阶段 7 · LM Studio 侧的两个认知修正

**修正一：`Serve on Local Network` 在哪。** 该开关不在主界面，需点工具栏 **Server Settings** 按钮在弹窗内开启（Enable CORS 同步开）。

**修正二（实测推翻先前结论）：不需要绑 `0.0.0.0`。**
`netstat` 显示 LM Studio **仅监听 `127.0.0.1:1234`**（未开 Serve on Local Network），但：

```bash
docker exec opengym-api-1 node -e "fetch('http://host.docker.internal:1234/v1/models')"
```

**成功返回模型列表**。即 Docker Desktop（Windows/WSL2）会对 `host.docker.internal` 做宿主侧代理转发，**无需绑 0.0.0.0**，反而更安全（LM Studio 保持仅本机可访问）。此前「必须绑 0.0.0.0」的提醒作废。

**可用模型**（`/v1/models`）：`qwen3.5-9b-deepseek-v4-flash`、`text-embedding-nomic-embed-text-v1.5`。

**「打不开网址」的真相**：LM Studio 根路径 `GET /` 返回 HTTP 200 + `{"error":"Unexpected endpoint or method. (GET /)"}` —— 这是**正常行为**，它不提供网页。正确验证地址是 `/v1/models`。

## 阶段 9 · 选远程访问方案：Tailscale

手机端接入需要 **HTTPS 稳定域名**。quick tunnel 每次重启换域名会废掉 passkey。

**选定 Tailscale**：免费、固定 `https://<device>.<tailnet>.ts.net`、不开放端口、仅 tailnet 内可访问。

下载官方安装包（38,718,976 字节，来源 `pkgs.tailscale.com/stable`）。注意：本会话 PowerShell 被沙箱拦截，且禁止从 Bash 调 `powershell.exe` → **无法自动校验 Authenticode 签名 / 无法静默安装**，需用户手动双击安装 + 登录 + 在管理后台开启 HTTPS Certificates。

**Tailscale 装好并登录成功**：

- 版本 1.104.1，CLI 路径 `C:\Program Files\Tailscale\tailscale.exe`
- HostName 与 DNSName 已脱敏
- Online true → 目标 HTTPS 地址即 `https://<your-device>.<your-tailnet>.ts.net`

**当前卡点**：`tailscale cert <domain>` 返回

```
500 Internal Server Error: your Tailscale account does not support getting TLS certs
```

→ 说明 **HTTPS Certificates 未在管理后台开启**。解决：管理后台 → DNS 页 → 拉到底 → **HTTPS Certificates → Enable**。

另注：`tailscale serve --bg` 在证书未开时曾静默 SIGTERM / exit 1（而 `serve reset` 却 rc=0），根因即证书未开。

## 阶段 12 · 手机端「教练无法运行」的根因定位

**现象**：手机端教练问候语正常显示，但生成计划时报「教练无法运行。需要实例所有者检查配置」。

**根因**：`data/coach.json` 的 `log` 字段给出真实错误：

```json
{ "outcome": "failed", "errorClass": "provider", "ms": 42454,
  "detail": "the answer was cut off at the output limit; try a smaller plan or a bigger model" }
```

深层原因：**LM Studio 以 `loaded_context_length=8192` + `PARALLEL=4` 加载模型** —— 8192 上下文被 4 个并行槽切分，**单次请求仅约 2048 token**，而教练规则提示词本身就有数千 token，输出必然被截断。

**硬件**：RTX 5060 Ti 8 GB（8151 MiB），9B Q4_K_M 权重约占 5.6 GB。

**修复动作（已执行并验证）**：

```bat
lms unload --all
lms load qwen3.5-9b-deepseek-v4-flash -c 16384 --parallel 1 -y
```

- ⚠️ `lms load` 对已加载模型会生成 `:2` 后缀新实例（openGym 配置的模型名不带后缀会命中旧实例），**必须先 unload 再 load** 才能拿到默认标识符。
- 验证：`lms ps` 显示 `CONTEXT 16384 / PARALLEL 1`；`/api/v0/models` 正常；显存 6986 MiB used / 907 MiB free；直连 `/v1/chat/completions` 连续生成 3000 token 成功。
- 已生成便捷脚本 `reload-model-16k.bat`（unload --all → load -c 16384 --parallel 1）。
- ⚠️ **CLI 加载参数不持久**：LM Studio 重启后需重新运行该脚本，或在 GUI 里把该模型的 Context Length 改成 16384 再加载。

## 阶段 13 · 手机连不上服务器排错

用户反馈手机端连不到服务器。从 PC 三处验证均正常：

- `docker compose ps` → api/web 均 Up healthy
- `tailscale status` → PC 与手机都在线、同一 tailnet
- `tailscale serve status` → 转发仍在
- `curl -kI` 域名返回 200
- `ping <手机 Tailscale IP>` 3/3 通

**结论：服务器 / 转发 / 证书 / 隧道全好，断点在手机侧。** 根因高度疑似**安卓厂商的激进省电管理后台杀 Tailscale**（VPN 类 App 易被清）。

- 临时验证：手机打开 Tailscale App 确认 Connected 再开 openGym。
- 根治：设置 → 应用 → Tailscale → 电池 → 关闭自动管理，勾选允许自启动 / 后台活动 / 关联启动；多任务界面锁定 Tailscale 卡片；设置 → 电池 → 更多 → 休眠时始终保持网络连接。
- 备选：同 WiFi 下改用局域网 HTTPS 直连绕开 Tailscale。
- 报错解码：`ERR_NAME_NOT_RESOLVED` = MagicDNS 未开；超时 = 隧道断；`Connection refused` = 端口问题。
